# 主人桌面长任务与不限时

## 现象与根因

用户需要长时间游戏操作。原界面只提供到10分钟，配置校验、桥接任务过期和运行时计时器还分别硬编码600000毫秒；到期即撤销后续桌面动作，即便任务尚未完成。基线 dev 4f0ce2f，隔离分支 feat/owner-desktop-duration，版本0.8.9。

## 完整逻辑

1. 链路：QQ设置的任务时限 → 专用授权API与共享校验 → QQ桥接任务 → 桌面运行时租约及定时器。所有截止条件统一，不只改下拉框。
2. 机制：缺省继续10分钟；显式 timeoutMs=0 表示不限时，有限值为30秒至24小时。界面提供原有选项及30分钟、1/2/4/8/24小时和“不限时（完成或手动取消）”。无限执行期限用JSON安全的null表示，不使用Infinity或setTimeout(0)。消息新鲜度、去重和待领取有效期仍有限，不能延后重放旧命令。
3. 影响面：QQ桥接和DSH插件两处运行组件，配置、领取、逐次校验、界面四类读取者，显式失败估算2×4×1=8。无限任务会持续消耗模型调用，但不增加工具或成员权限。
4. 取舍：仅把10分钟放大成常数成本低，却仍中断游戏且多处易漂移；采用共享时限语义和显式不限时，保留逐次授权检查与原Windows人类开关，回滚只涉及时限代码与一项设置。
5. 生效：本机集成后重载SurfCore插件、重启QQ桥接；通过专用设置API把当前已授权管理会话设为不限时。修改时限先取消旧任务并更新授权代际。保持二代仿真、QQ/B站、双远程与preserve-local更新。
6. 验证：模拟时钟跨越10分钟/24小时检查有限和无限任务；取消、主人变更、完成和断连仍撤权；null/空字符串/布尔值不允许误转不限时；真实设置API回读0及最长时限，另跑相关插件、桥接与必需审计。
7. 回滚：先改回10分钟并取消任务，再回退代码、重载插件和桥接。不得清空任务来源/拒绝记录或自动恢复旧任务。

## 使用语义

不限时只移除自动总时限。任务完成、模型结束、主人取消、授权关闭或连接失效仍会结束；不会让结束的子代理永久取得权限。主人入口可持续保持启用，后续新命令继续可用。管理会话需保持运行且Computer Use开关开启。长时间游戏可以发送“电脑：继续玩这个游戏，直到我让你停止”；停止发送“取消电脑任务”，群内需主人真正@机器人。

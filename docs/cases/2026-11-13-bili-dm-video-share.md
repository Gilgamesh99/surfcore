# B站私信视频 → 指定QQ群 → 真实结果回报

## 现象与根因

用户先发视频卡片，再要求分享到指定群并附上想法，机器人没有回应。只读现场记录显示卡片与文字相隔一秒，之后出现机器人的主动通知。旧 dm-await 只读 get_sessions.last_msg；卡片被后续文字覆盖，自己的通知也会推进时间水位。它在模型接收之前保存游标，子进程失败还可能被当作无消息。既有 share-now 从公共素材池选片，并不接受私信中的指定视频和群。

## 完整逻辑

1. **链路**：DSH 插件 scheduler 调用 dm-await；读取器用固定 B站 GET 接口拉取会话历史；先把每条输入转为本地任务并持久保存，再确认收件批次。模型拿到有序消息和绑定的视频，通过 dm-task 调用本机 QQ 桥接的专用接口；桥接取得 OneBot 消息编号后记录回执；插件通过现有 B站 dm 发送器回报结果。
2. **机制**：水位改为精确消息序号，稳定批次支持重复读取/确认。真实接口使用 msg_seqno，兼容旧 msg_seq，冲突或不安全数字停止确认；不使用不精确的 msg_key。type=7/source=5 卡片的 aid 通过公开 view 接口解析为 BV；视频与随后文字一起交付。确认前已有独立任务负责后续重试，模型排队或发送失败不会丢输入。
3. **影响面**：DSH 插件、短期 CLI 子进程、QQ 桥接共三种运行环境；四个入口为定时收件、模型命令、设置页、桥接路由，按 3×4×1=12 估算。涉及角色私信任务、B站账号请求及 QQ 群发送；原始私聊不进入公共素材池。读取本身不调用模型；模型任务仍受 token/互动/角色限制。
4. **取舍**：仅补视频解析或改提示词成本低，但无法解决漏信、重复发送与没有回执的问题；采用独立任务记录与受限交接接口，增加小型状态模块，换取可恢复、可核对的交付。私信不直接加入跨平台公共记忆。
5. **生效**：集成后需要重载 DSH SurfCore 插件（scheduler/API/client）并重启 QQ 桥接；CLI 每次调用加载当前文件。刷新现有 GUI 后验收“B站 → 私信任务”。本次未执行部署或真实 GUI 验收。
6. **验证**：按下表完成模拟收件/真实命令分发/实际宿主排队/桥接路由和回执验证；另做固定 GET 的现场格式检查，详见实测限制。
7. **回滚**：停止插件与桥接，备份当前角色的 dm-await-state.json、dm-tasks.json 及 QQ 平台 bili-dm-share 目录，再撤回本功能提交并重启。不要删除发送记录或把旧游标备份直接覆盖到生产，否则可能重复处理；旧轮询器不理解新批次的所有权。

## 行为与边界

- 只把当前配置主人的直接肯定分享请求转为群分享任务；疑问、否定、取消、多个目标、截断指令不会被当作单群授权。普通私信继续走回复任务。
- 精确匹配 QQ 白名单内的群号或规范化群名。重名、不在白名单、视频不明确均给出错误及下一步，不猜群。
- 使用单条文字消息：视频标题、标准 BV 链接、模型写的简短想法。沿用现有稳定的文字卡片方式。模型先读取视频信息，不编造观看经历或来源，也不转发私聊原话。
- 专用桥接只接受控制台管理员认证，拒绝 x-agent-token/x-agent-call 的 QQ 会话越权；保留模式、黑白名单、暂停/静默、发送工具开关、字数、频率、鱼群与 token 发送保护。
- 请求绑定原主人、消息序号、群与内容。发送前持久化一次性标记，成功必须取得非零 OneBot 消息编号；不进入通用 outbox 自动重发。发送结果不确定时保存 unknown，不能换任务号绕过去。
- 群发送成功后，B站回报使用现有登录、关系、身份与发送限制；B站 API 接受回报与 QQ 群回执分开记录。回报失败只重试回报，不重新发群；结果未知时停止自动重试。
- 角色 id/epoch 和主人身份在执行时复核。迟到的群解析失败不能覆盖 sent；私信回报使用 attemptId/key 核对，旧回报不能覆盖新结果。
- 发送、普通回复或回报中断超过90秒仍无可信回执时显示 unknown；旧失败记录或 NOT_FOUND 不能证明本次没发过。
- 设置页显示收件错误、排队/发送/回报状态和具体下一步；只给确定可安全重试的失败显示按钮，不展示原始私聊正文。
- 收件风控暂停15分钟，其他读取失败延后1分钟，延后时间持久化；已接收的任务仍可继续处理。

## 预算与迁移

- 读取默认12秒总预算，最多5页/100条/20个GET，每页20条；保留最近8条、30分钟内的视频上下文。未覆盖到旧水位则失败，不跳过积压。
- 模型每次最多入队5个任务，动作预算8；排队租约10分钟，最多3次后显示失败；任务记录最多2000项/16MB，满或损坏时不确认新消息。
- 首次无状态只建立基线；旧 lastSeen/seen 时间水位兼容迁移，同秒不能恢复先后会显式提示。旧程序已经推进水位的漏信不会自动重放；需要用户重新发起新请求，避免突然发送历史内容。
- 锁文件不会按超时盲删；持续锁定时提示先停止插件并核对持有者后备份处理。

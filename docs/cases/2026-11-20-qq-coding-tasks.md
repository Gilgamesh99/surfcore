# QQ 主人开独立编程会话，向原会话交付附件

## 起因

同学群里一次 FPS 制作请求得到多段 HTML。对方随后索要文件，但 QQ 聊天会话只交付了文字。独立 DSH 编程会话具备工作区、命令执行和验收工具。两条链路需要通过一个可查进度、有原始收件人和附件回执的任务连接起来。

## 用法

| QQ 中的说法 | 行为 |
| --- | --- |
| 主人说“在新会话中，做一个可下载的温度换算器”或“在新会话中＋离线版 FPS 游戏” | 建立独立工作区和 DSH 会话，向发起处回复一个八位任务编号。 |
| 主人说“开个新会话” | 先开空会话。主人可在原处发送“任务 #编号：做一个温度换算器”。多个空会话用编号区分。 |
| 主人单独说“做一个 FPS 吧” | 没有正在等该主人补充的空会话时，交给普通聊天处理。 |
| 原群成员或主人私聊问“任务 #编号 进度怎么样了” | 查询宿主确认的排队、制作、运行验收、等待人工处理或文件送达状态。主人私聊可查其发起的各个任务。 |
| QQ 明确拒收后，主人说“重试交付 #编号” | 重新核验成品，只补尚未成功送达的附件。回执不明时请先核对原会话实际收到的文件。 |

## 完整逻辑

QQ 桥接在原有聊天入口识别当前 OneBot 连接的实时消息，核对登录账号、真实发送者、会话和白名单。主人明确要求开启新会话，桥接才登记任务。群友可以查本群进度。引用、转发、重放、被拉黑的人和其他群的任务编号均不能授予权限。状态文本只展示编号、阶段及文件计数。

任务独占一个工作区，通过 DSH 正式工作区和会话接口提交，沿用标准编程工具、工作区写入和人工审批。宿主会话标题含 QQ 任务编号。桥接跟踪该次请求的运行、提问、审批与结束事件，重连后从宿主历史恢复。批准操作或答复宿主提问需要主人在 DSH 中处理。工作区、任务提交和宿主会话标识可在重试时对应起来。

编程会话生成成品，并在本次任务的工作区根目录执行对应的前台 Node 验收。桥接按宿主记录还原执行时的目录，会话中途切换目录后须回到任务根目录重跑。成功结束后，桥接检查验收记录、清单和文件，拒绝目录跳转、链接、重名、清单外文件以及预算外内容。一次最多 32 个文件，单件 32 MiB，合计 64 MiB。桥接将验过的字节交给 SnowLuma 的群文件或私聊附件接口，按每份文件的原会话、大小、摘要和返回的文件编号记账。任务号、所属会话、任务说明与回执保存在桥接本机，重启可恢复。

这里选择独立 DSH 会话和按来源受限的桥接上传。给共享 QQ 会话直接开放文件系统与通用上传，会让群消息参与决定本机文件及收件人。只向群里贴代码也缺少可运行附件和回执。新增行为涉及 QQ 桥接、主人发起的独立 DSH 任务和 SnowLuma 的指定会话附件动作。只有开始制作才会使用编程模型额度。

## 故障处理与回滚

- DSH 离线时查询显示最近确认的阶段。待审批、待回答时，按编号在 DSH 打开相应会话。执行失败、缺少成功验收或文件内容变化时，任务状态会指出需要检查的环节。
- 网关明确拒收会提示处理权限或文件限制。超时、回执缺少文件编号、或桥接在上传中途重启时，保留已确认和待核对记录，避免用户收到重复附件。
- 合并后重新启动 QQ 桥接即可加载。回滚可以撤销本功能合并并重启 QQ 桥接。保留已建的 DSH 会话、工作区与任务记录，可继续在 DSH 查看成品和运行历史。

## 验证与发布交接

同时修复了协议回归里已有的 QQ 文本格式耗时问题。R11 两次分别耗时 1389 和 1021 毫秒，超过 500 毫秒门限。Markdown 图片和链接都要求右括号。没有右括号的输入可以跳过两次匹配。保留原有计时断言与转换用例。[QQ 文本格式](../../src/md-to-plain.js)

Windows 的更新测试会多次启动 PowerShell 打包。在整仓运行中两次达到 60 秒的外层时限，单独完成约需 66 秒，因此该用例在 Windows 上获得 120 秒的总时限。用例自身的产物、校验及回滚断言继续执行。

覆盖正式入站分流、宿主 RPC 和事件还原、成品校验、SDK 附件回执和桥接重启。集成用例实际运行温度换算 CLI，再运行从内存网关取回的附件。独立 DSH 抽查另外制作了一个数字乘二工具，前台 TAP 验收通过，取回的附件以 21 为输入，输出 42。冷恢复用例在原工作区放入答案 41，在另一目录放入答案 42 并实际通过同名测试，要求桥接重启后仍向原群交付 0 个附件。测试使用隔离工作区与模拟 QQ 收件人。

建议 minor。QQ 桥接新增可选交互，普通聊天和旧状态兼容。变更涉及 [QQ 入站](../../src/qq-coding-intent.js)、[宿主会话](../../src/qq-coding-dsh.js)、[任务状态](../../src/qq-coding-tasks.js)、[附件交付](../../src/qq-coding-delivery.js)、[桥接接线](../../src/bridge.js)和[端到端回归](../../scripts/test-qq-coding-flow.mjs)。全量门禁为 `npm run test:audit`，协议回归为 `npm run test:regressions`。真实 QQ 客户端收件和实际群文件配额仍取决于部署时的账号与网关。

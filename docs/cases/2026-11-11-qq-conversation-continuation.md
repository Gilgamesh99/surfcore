# QQ 回答几句后断聊，重新 @ 才回复

## 现象与证据

用户反馈：群里正常接着聊时不回，重新 @ 才回。2026-11-11 实际会话在 14:33:59 回答后只等待 30 秒，14:34:46 调用 close；14:35:42 的“原神和命运二你更喜欢哪个”进入未读，直到 14:43:52 再次 @ 才被模型处理。14:49:06 的“你现在去了解一下”也留在未读，14:58:23 被 @ 后才处理。

基线：SurfCore 0.8.9 / `0ce8580`。本机主仓库已有无关 package-lock.json 改动，修复在独立 `fix/qq-continuation` 工作树完成。本地没有 dev 分支，使用运行版本 HEAD 作基线，不切换主仓库分支。

## 根因

- `qq_close_conversation` 豁免五分钟沉睡观察，并取消 replyCheck；模型把一次 30 秒没有新消息当作话题聊完。
- 默认 diving / infinite / anyMessage=false / probability=.05 没有“刚聊过的人继续接话”的路径。
- 收尾分类识别“哪个”，唤醒的 isDirectedAtAi 另用不完整正则，漏掉自然追问/请求。
- reopenClosure 只设置 reopenedAt，软冷却仍看 cooldownUntil。@ 后发出的回复也继续跳过 replyCheck。

## 完整逻辑

- **链路**：QQ 入站 → bridge 的地址/群规模/鱼群判断 → 有限续聊或常规唤醒 → 同一套额度/通道检查 → DSH；模型成功发送后，用已展示入站的参与人记录续聊期限。close 可以结束当前模型回合，但短暂安静时保留续聊资格。
- **机制**：续聊是成功回复产生、按人限时的事实，不由模型宣称“我在聊”产生。只用已展示的本地消息水位，最多 8 人，每人独立期限；默认 300000ms，可用 `socialV2.wake.continuationWindowMs=0` 关闭。读取/唤醒/发送失败不授予资格，旧消息不会因为无关主动发言反复续期。
- **影响面**：一个 QQ bridge 进程；纯逻辑模块与 bridge 的状态读写、收尾工具结果。主要影响小群 reserved2，私聊、大群、白名单、黑名单、鱼群、费用和每日唤醒额度保留。新增状态只存参与人 ID 与时间，不另存消息正文。相比旧行为会增加有效续聊的模型调用。
- **取舍 A（配置全群 active）**：成本低，但所有成员都可唤醒，扩大参与和费用，无法修正“重开仍冷却”。回退配置容易，但语义不合适。
- **取舍 B（只补问句正则）**：成本低，可恢复两条示例问句，但普通接话仍靠 5% 概率，不能覆盖“聊到一半断掉”。
- **采用 C（有限参与人窗口 + 重开解冷却 + 共用分类）**：新增一个有界纯模块与桥接接线，避免改成全群 active。状态窗口到期自动无效，回滚源码后旧状态字段可被忽略。
- **生效**：bridge 在进程启动时 import 源码，修改后需要重启 QQ bridge；只刷新网页不生效。无需修改 DSH 宿主、B站调度、语音服务或前端构建。

## 修法与边界

1. 成功文本/表情/语音/拍一拍回复后，记录已看到的人类参与人，引用/@ 目标优先，未看/鱼群/指向他人的消息不参与推断；部分成功也保留真实目标。
2. 小群同一参与人在五分钟内接话，使用 continuation 唤醒；@ 其他人/引用他人不算续聊，大群不启用此路径，明确道别移除对应参与人。
3. 共用 classifyMessage 与提问/请求识别，覆盖无问号的“你更喜欢哪个”“你现在去了解一下”；第三方问题不再误堵 close。
4. 明确重新开聊时结束旧软冷却；仍保留摘要和 reopenedAt 供下轮提示使用。
5. 最近刚回复实质内容、参与人窗口尚在、双方尚未收束时，close 返回 `ok:true, deferred:true, code:CONTINUATION_WINDOW_OPEN`。只按安全水位确认已读，标记当前模型回合可以结束并取消空转回访，不写 topic-done/20 分钟冷却，不要求连续空等。真实道别/附和收束或窗口过期后按正常 close 处理。
6. 经桥接验证的 continuation 可豁免节奏间隔（遵守 directBypassGap 配置），但不会因此豁免每日计次、费用或单轮发送上限。未验证的 reason 字符串不能取得豁免。
